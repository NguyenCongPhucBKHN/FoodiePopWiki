Mô tả

  • Mỗi máy được server ABI cấp một ServerID số (Live: 584553) gắn với mã thiết bị (DEI...) hoặc tài khoản Google Play Games (GPG); mọi tính năng xã hội (đội, bảng xếp hạng, Weekly, hộp thư) chờ ID này sẵn sàng rồi mới chạy.
  • Nếu có tài khoản nền tảng, client liên kết nó vào ServerID (lệnh rn); nếu server và máy lệch ID thì server thắng, ID cũ ghi vào lịch sử.
  • Save lên cloud là thủ công: nút Save Progress trong Settings đồng bộ lên server ABI (sg / lg) bằng bộ mã hoá SaveGameCodec (đã có từ 1.11, 1.15 sửa lại), có popup so sánh local / server.
  • Google Play Games cloud save có thư viện (PlatformServicesR1) nhưng không có lớp cụ thể nào dùng trong 1.15.
  • PlayerServerIdentity (mới 1.15) lưu cặp (ServerID, TeamID) vào hồ sơ lõi để ID sống sót khi Clear Data.

Tóm tắt thiết kế

  • Code Server là nguồn chân lý của ID: nếu ID lưu trên máy khác ID server ánh xạ cho thiết bị thì server thắng và ID cũ vào lịch sử.
  • Code Auth theo tầng: DEI (thiết bị) → GPG (Google Play Games) / AGC (Apple); liên kết bằng rn để cài lại vẫn lấy lại hồ sơ.
  • Code Save lên cloud thủ công (nút Save Progress), có bước so sánh local / server và chỉ ghi đè khi người chơi chọn; server chặn bản cũ bằng vrs, aV, pl.
  • Code Bản save lên server (SaveGameCodec, có từ 1.11; 1.15 thêm PlayerServerIdentity) gồm 3 khối: core (CookOrder), r1 (Profile, Team, Leaderboard, Weekly, EventSale, Segment) và st (thống kê IAP / analytics).
  • Live 16/11 Máy test dùng ServerID 584553, authKind DEI: chưa liên kết tài khoản nền tảng.
  • Nhận định Google Play cloud save (PlatformServicesR1) có thư viện nhưng chưa nối: bản này chỉ có một kênh save server ABI.

Vận dụng cho game khác

  • Để server quyết định ID (thay vì client) và lưu lịch sử ID cũ giúp xử lý trường hợp một người nhiều máy mà không mất hồ sơ.
  • Save thủ công có so sánh hai bên (Day, gem, xu, IAP) tránh ghi đè nhầm; thêm khoá phiên bản vrs để chặn bản cũ.
  • Giữ cặp (ServerId, TeamId) trong hồ sơ lõi để dữ liệu xã hội không phụ thuộc vào save phụ của tính năng.

Bảng tổng hợp mọi tính năng đã làm chi tiết: FoodiePop_ThietKeChiTiet.xlsx.

Mở khóa & điểm vào

Không có ngưỡng level: ABIServerAPI.InitConnection chạy khi khởi động, ResolveIdentityBeforeConsumers chạy nền cho tới khi có ID. Nút Save Progress nằm sẵn trong Settings (SaveProgressButton, Button_SaveProgress). Server chỉ nhận save khi đã có ServerID và CookOrderSaveSync.IsReady.

Điểm vào:

  • Khởi động game: ABIServerAPI.InitConnection (log mode / URL / pjProfile / pjInbox)
  • Nút Save Progress trong popup Settings (SaveProgressButton.OnClick → SaveGameManager.SyncDataWithServer)
  • Popup lỗi đẩy dữ liệu có nút Retry (PopupPushDataFailedCtrl.RetrySync)
  • Mọi tính năng server (Team, Leaderboard, Weekly, Inbox, Profile) gọi ABIServerAPI.WaitForIdentityReady

Cách hoạt động

  1. InitConnection ghi log, chạy CheckNetworkConnection (lặp ~3,3 s, dò WebService.IsActive / internetReachability) và ResolveIdentityBeforeConsumers.
  2. Đọc ServerID đã lưu (PlayerPrefs khoá FoodiePop_ServerID) và SocialAuthID (FoodiePop_SocialAuthID); lấy auth máy DEI + base64(deviceUniqueIdentifier) (SocialAuth.GetDeviceAuthID).
  3. Thử đăng nhập Google Play Games (SignInPlatformAuthID, timeout 10 s) để có auth GPG....
  4. ResolveServerId: gọi rdn (đọc ID theo auth máy); chưa có thì gn (sinh ID mới); đã có ID lưu mà khác ID server → "the server mapping wins".
  5. Có tài khoản nền tảng: ResolveWithPlatform gọi rn (link ID ↔ auth nền tảng); thất bại ghi cảnh báo, xung đột thì SetIdentityConflict và thử lại.
  6. PublishIdentity(serverId, authKind) đặt ABIServerAPI.ServerID, AuthKind, IsIdentityReady = true, thêm ID cũ vào lịch sử, gọi ProfilePopupRouter.OnIdentityChanged.
  7. Hồ sơ lõi nhận cặp (ServerId, TeamId) qua CookOrderBridge.SetCoreServerIdentity (PlayerServerIdentity).
  8. Người chơi bấm Save Progress: SaveGameManager.SyncDataWithServer so save local và server (lg), tự đẩy lên nếu server trống, hoặc hiện PopupSyncDataCtrl để chọn.
