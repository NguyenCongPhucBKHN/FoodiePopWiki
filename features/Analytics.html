Mô tả

  • Game gửi sự kiện tới 3 SDK: Firebase Analytics (kênh chính), AppsFlyer (cài đặt, vòng đời quảng cáo, mua hàng, mốc level, doanh thu quảng cáo) và TikTok App Events (chỉ doanh thu quảng cáo MAX, khi có credentials). Danh mục dựng từ mã máy (Tools/decode/analytics_events.py) đếm 64 sự kiện (Firebase 48, AppsFlyer 15, TikTok 1) ở 69 nơi gọi, 21 user property và 2 key Crashlytics; bảng đầy đủ ở phụ lục Sự kiện analytics. AppMetrica không được code game gọi; SDK AppMetrica (Yandex) chỉ đi kèm adapter quảng cáo Yandex của AppLovin MAX (META-INF/io/appmetrica, META-INF/com/yandex/android/mobileads trong APK) và tự ghi dữ liệu trên máy (no_backup/appmetrica, Live 16/11).
  • Sự kiện Firebase đi qua DataTrackingManager.LogEvent (module R1 qua TrackingManager.FirebaseLogEvent → CookOrderBridge.LogEvent), AppsFlyer qua DataTrackingManager.AppsFlyerTrackEvent; chỉ gửi khi Firebase khởi tạo xong và IsAllowTrackingData bật (bản release bật, bản test tắt).
  • Bộ sự kiện xoay quanh level (level_start / level_end, checkpoint_start / checkpoint_end, customer_*), tiền (currency_earn / spend, booster_earn / spend), quảng cáo (ad_inter_show, ads_reward_*, ad_impression, af_inters_*, af_rewarded_*), IAP (iap_show, iap_click, iap_purchase_result, iapPurchased_confirmed, purchase, af_purchase) và LiveOps R1 (Weekly Contest, Stage Race, Dreamy Tower, Foodie Streak, Foodie Pass, Segment, đồng bộ save).
  • Một số mốc chỉ gửi một lần nhờ cờ lưu (Analytics_CheckpointStart_<i> / Analytics_CheckpointEnd_<i> trong progress của map, af_first_open trong PlayerPrefs). 6 sự kiện có code gửi nhưng không thấy nơi gọi trong 1.15: first_ads, vm_<UserBucketTracking._iaaConfig.ids[i]>, rise_iap, level_dish_serve, app_start_by_notification, rate_star.

Thiết kế chi tiết

Cập nhật 17/11/2026 · danh mục máy (gắn tên sự kiện qua mã máy arm64), chưa kiểm trên DebugView

Codeđọc từ pseudo-C / dump của APK 1.15APKgiá trị mặc định đóng gói trong APKLive dd/mmserver / remote config / save thật của ngày đóPlaytestthấy khi chơi thật, có ảnh chụpNhận địnhsuy luận thiết kế, không phải số liệu đọc được

Tóm tắt thiết kế

  • Code 64 sự kiện ở 69 nơi gọi, gắn tên qua mã máy: tên là chuỗi nạp vào thanh ghi tham số ngay trước lệnh gọi hàm gửi, tham số là các Firebase.Analytics.Parameter trong mảng / list truyền vào; wrapper DataTrackingManager.LogEvent, TrackingManager.FirebaseLogEvent được lần ngược tới nơi gọi.
  • Code Checkpoint là hai sự kiện checkpoint_start / checkpoint_end: DataTrackingManager.FlushPendingCheckpoints chọn tên theo cờ isEnd; mỗi level chỉ một lần (lần đầu bắt đầu, lần đầu thắng) nhờ khoá Analytics_CheckpointStart_<i> / Analytics_CheckpointEnd_<i>.
  • Code Mốc doanh thu đặt tên lúc chạy: vm_ + id bucket (UserBucketTracking.GetKeyTrackingBucketIAA), watch_<mốc>_reward / watch_<mốc>_ads (UserAdsClassifyTracking.GetKeyTrackingRevenueReward).
  • Code 6 sự kiện có code gửi nhưng không có nơi gọi trong 1.15 (first_ads, vm_<UserBucketTracking._iaaConfig.ids[i]>, rise_iap, level_dish_serve, app_start_by_notification, rate_star): số liệu Firebase của bản này sẽ không có chúng.
  • Code Bản release bật isTrackingData, bản test tắt, nên build thử không làm bẩn dữ liệu thật.
  • Nhận định Bộ sự kiện đủ để studio tính retention D1/D7, funnel từng level và điểm thua, ARPDAU quảng cáo, funnel IAP và bảng cân đối tiền; xem bảng KPI bên dưới.
  • Nhận định Bộ user property (camp_name, media_source, Level_accumulative, user_retention, seg_*) đủ để cắt mọi báo cáo theo nguồn cài, tuổi người chơi và nhóm Segment; hợp với mô hình UA trả phí có ROAS.

Luồng người chơi từng bước

  1. Firebase sẵn sàngHệ thống Code
    DataTrackingManager.SetUpOnDoneInitFirebase gửi AppsFlyer first_open_app một lần, gắn user property, đẩy hàng đợi checkpoint.
  2. Vào levelHệ thống Code
    CakeOrderDataTracking.BeginLevel gửi level_start, xếp checkpoint_start lần đầu.
  3. Phục vụ kháchHệ thống Code
    CakeOrderDataTracking.RecordCustomerStart / RecordCustomerEnd gửi customer_start / customer_end.
  4. Kết thúc levelHệ thống Code
    CakeOrderDataTracking.CompleteLevel gửi level_end; thắng thì thêm checkpoint_end lần đầu và AppsFlyer af_level_achieved.
  5. Tiền, quảng cáo, mua hàngHệ thống Code
    DataTrackingManager.TrackCurrencyChange, AdsDataTracking.InterDisplay, DataTrackingManager.TrackIapClick, DataTrackingManager.RecordIapPurchase gửi theo từng hành động.

Vận dụng cho game khác

  • Đặt cổng bật / tắt tracking theo loại build ngay lúc boot để bản test không làm bẩn dữ liệu.
  • Đo level ở 2 tầng: sự kiện mỗi lượt chơi (level_start / level_end) và mốc một lần mỗi level (checkpoint_*) cho funnel sạch, có cờ chống gửi trùng trong save.
  • Chuẩn hoá source/placement cho mọi giao dịch tiền để một bảng cân đối kinh tế dùng được cho mọi tính năng.
  • Kiểm định kỳ rằng mọi hàm gửi sự kiện đều có nơi gọi: 1.15 còn 6 sự kiện viết sẵn nhưng không bao giờ gửi.

Mở khóa & điểm vào

Luôn chạy sau boot. DataTrackingManager.LogEvent thoát sớm nếu _state != 2 (Firebase chưa xong) hoặc IapAdsGlobalConfig.IsAllowTrackingData = false. Bản release đặt isTrackingData = true trong BootGameCookOrder.IEBootSequence; bản test đặt false.

Điểm vào:

  • Boot: FirebaseModulesManagers.Init → SetUpOnDoneInitFirebase (first_open_app)
  • Vào / kết thúc level: CakeOrderDataTracking.BeginLevel, CompleteLevel
  • Quảng cáo: AdsDataTracking (inter, reward, banner, doanh thu)
  • Mua hàng: AdsDataTracking.ClickIAP, PurchaseDone
  • Thay đổi tiền / booster: DataTrackingManager.TrackCurrencyChange, TrackBoosterChange
  • R1 manager gọi TrackingManager.FirebaseLogEvent

Cách hoạt động

  1. Boot dựng profile: release isTrackingData = true, isAutoFetchPreviousPurchase = true; bản test tắt tracking.
  2. FirebaseModulesManagers.Init khởi tạo Firebase (timeout "Firebase: Init Timeout"); xong thì DataTrackingManager chuyển state 2 và gọi DataTrackingManager.SetUpOnDoneInitFirebase: gửi AppsFlyer first_open_app đúng một lần (khoá PlayerPrefs af_first_open), dựng user property, đẩy hàng đợi checkpoint.
  3. AppsFlyerBootstrap chờ session sẵn sàng (không quá thời gian chờ) rồi bật SDK; dữ liệu attribution (media_source, campaign, af_campaignID) ghi vào UserAnalyticsState và PlayerPrefs.
  4. DataTrackingManager.SyncUserProperties gắn 12 user property từ UserAnalyticsState (JSON trong PlayerPrefs analytics_user_state_v2); Segment gắn thêm 6 property seg_*.
  5. Trong game, mỗi manager gọi DataTrackingManager.LogEvent(tên, Parameter[]) → FirebaseAnalytics.LogEvent; mua hàng, thắng level, mốc nội dung và vòng đời quảng cáo gọi thêm DataTrackingManager.AppsFlyerTrackEvent; doanh thu MAX còn đi AppsFlyer.logAdRevenue và TikTok (TikTokAppEvents.OnMaxAdRevenuePaid).
  6. Lần đầu bắt đầu / thắng mỗi level, CakeOrderDataTracking.TrackCheckpointStart / TrackCheckpointEnd xếp một CheckpointEvent (isEnd = 0 / 1) vào UserState.pendingCheckpoints nếu progress của map chưa có khoá Analytics_CheckpointStart_<i> / Analytics_CheckpointEnd_<i>; DataTrackingManager.FlushPendingCheckpoints gửi checkpoint_start / checkpoint_end khi Firebase sẵn sàng.
  7. DataTrackingManager.TryTrackMainContentCompleted (khi pause hoặc khi xong nội dung) gửi AppsFlyer af_complete_rq_all, không lặp trong cùng ngày.

Còn thiếu / chưa xác minh

  • Chưa thấy kiểm tra consent (UMP) trước khi gửi analytics; consent_config mặc định mode 0 = không hiện form (xem BootAndConsent).
  • Không kiểm được trên thiết bị xem Firebase / AppsFlyer có nhận sự kiện (không dùng DebugView); tần suất và điều kiện gửi đọc từ code.
  • 6 sự kiện (first_ads, vm_<UserBucketTracking._iaaConfig.ids[i]>, rise_iap, level_dish_serve, app_start_by_notification, rate_star) không có nơi gọi: đã quét lệnh BL / B của mọi method game, slot MethodInfo (delegate), override / interface, m_MethodName trong rip và chuỗi tên hàm; chưa loại trừ gọi bằng reflection từ thư viện ngoài.
  • Sự kiện SDK tự gửi (first_open, session_start, ad_impression tự động của Firebase / AdMob, auto track của TikTok) không đi qua code game nên không có trong danh mục.
  • Cột giá trị trong phụ lục là tập bao (mọi chuỗi có thể tới tham số), không phải phân phối thực tế; vài tham số tính toán (duration_complete, sec_since_load, value của watch_*) chỉ có nguồn, không có giá trị.
  • AppMetrica không được code game gọi; SDK AppMetrica (Yandex) chỉ đi kèm adapter quảng cáo Yandex của AppLovin MAX (META-INF/io/appmetrica, META-INF/com/yandex/android/mobileads trong APK) và tự ghi dữ liệu trên máy (no_backup/appmetrica, Live 16/11).
